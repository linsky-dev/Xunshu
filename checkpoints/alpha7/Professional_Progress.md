# 寻枢 Xunshu alpha.7：80 分目标阶段进展与放行审查

日期：2026-11-24。基线：`0.18.0-alpha.6`（上一轮综合成熟度 65/100）。当前：`0.18.0-alpha.7`。本报告为开发检查点，不是最终发行说明。

## 1. 结论

本轮实际修改 15 个文件（含版本和文档），无新增 Cargo 第三方依赖。基于同一权重的主观工程成熟度评估为约 **76/100**，比基线上升 11 分，距离 80 分仍差 4 个加权分；严格超过 80 需要再取得更多证据。不能用测试数量、合成数据或代码完成率替代专业软件真实安装、实际文档和持续运行的验收。遵照用户要求，不生成最终完整工程包、正式安装包或 ReleaseReady 归档。单独保留可重建的开发差异补丁和原始证据，避免丢失进度。

## 6. 跨过 80 分的优先验收条件

1. 用锁定真实模型执行 Linux OCR/语义抽取、检索、损坏模型拒绝及完整安装生命周期；带真实 PDF/Office/扫描混合语料，不只合成文本。补真实推理内存、耗时和准确率证据。
2. Windows 原生工具链构建及 Win10/11 隔离目录实际首次安装、覆盖升级、失败补偿、回滚、卸载、旧数据保留，验证真实 NTFS 与 USN 监控、系统对话框、中文输入法。Linux UOS/麒麟仍分别实机验证，不能凭 Debian 通过声明。
3. 优化最宽 OR 完整查询，目标 P95 50ms；在同硬件同文件集同参数下复测，记录首屏与全量区别。扩大正文 Release 到 10 万实际样本，长期运行与故障注入（磁盘满、权限撤销、目录热插拔、进程强制终止、休眠唤醒）；明确模型/向量预算，设计 ANN 必须有召回率真值。
4. 维持开源许可证复核、模型来源及通知、离线运行约束；发布之前仍需签名与平台支持矩阵。

以上不是承诺完成后自动加分；必须按同一标准重新审查证据。优先补模型和 Windows 环境是当前缩小差距最快的方式。

### 需要补充的环境

现有 Rust 1.99.1 与 Cargo Vendor 不用再次下载。源码已有 `rust/scripts/prepare-models.py`，按 `rust/docs/RECOVERY.md` 安装准备环境（PyTorch CPU 2.8.0、Transformers 4.51.3、ONNX 1.17.0、ONNX Runtime Python 1.20.1、PyYAML）。在联网电脑从 `rust` 工作目录运行：

```powershell
python scripts/prepare-models.py --cache D:\Xunshu-model-cache --output D:\Xunshu-resources-linux --platform linux
python scripts/prepare-models.py --cache D:\Xunshu-model-cache --output D:\Xunshu-resources-windows --platform windows
```

输出目录必须不存在。上传完整 Linux 资源目录的 ZIP，保留清单、模型卡、许可、运行库和权重；Windows 资源可在本机留存供验证。脚本按源码锁定的 BGE、PP-OCRv5 和 ONNX Runtime 版本生成，下载或转换失败时保留实际错误，不随意替换模型版本。真实 Windows 验收还需原生 Windows、Rust MSVC 与 Visual Studio Build Tools C++ 桌面构建组件；Linux 交叉编译不能代替实机。不要上传私人真实文档或密码。
