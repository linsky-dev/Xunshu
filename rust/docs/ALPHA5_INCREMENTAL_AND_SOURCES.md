# 寻枢 0.18.0-alpha.5：增量索引、来源扩展与可靠性修复

日期：2026-11-23；依据当前工作区实际源码、离线编译/测试结果。**工程预发布版，不是已签名安装包。**

## 已落地（本版本）

1. **正文持久快照的差分 SQL 更新**：先加载授权 token、模型指纹和 SHA-256 都验证通过的旧正文库到独立可写内存副本；用文档修订号判断未变化文件，保留其 `segments`、FTS 倒排项及向量；修改文档删除旧段落和向量后再写入；删除/不再收录的文档一起移除。完整确认后原子发布 `content.idx`。失败或取消时不发布候选快照；零变化复用旧代次。
2. **空文档修订记录**：对空 `.txt` 和其他抽取结果为空但已验证的文件保留 `documents` 行、零 `segments`。避免每轮重复解析或无意义更新代次。该修复不使空文件成为检索命中。
3. **可解释正文结果**：`MatchEvidence` 标识关键词、离线语义、双路命中；界面可以显示可信的搜索证据，但不把相似度当作确定性命中。
4. **离线静态来源**：本地 JSON 清单与数据由用户明确授权导入，不运行代码，不主动联网；`src:` 可限定来源查询；撤销后立即清理内存中的来源数据和匹配缓存。
5. **链接校验**：书签和静态来源网页入口统一使用 `allowed_web_uri`，要求 HTTP(S)、非空 host，拒绝 URL userinfo、裸控制字符、空白和反斜杠。既在载入时校验，也在界面点击时二次检查。潜在敏感路径/查询参数不展示在书签标题和摘要中。**用户主动点击网络书签仍可能打开外部浏览器访问网页，不能宣传“点击书签也完全不联网”。**
6. **失败诊断**：正文索引不发布时显示失败数和首个失败路径/原因，旧有效索引继续存在；搜索时仍隐藏已经变更或撤销授权文件的旧命中。
7. **交付一致性检查**：`scripts/check_release_consistency.py` 只读校验工作区版本、8 个成员、`Cargo.lock` 和工具链声明；可供打包前执行，不替代签名或实机验证。

## 关键不变量与测试

- 允许增量复用的前提：旧快照 SHA-256 完整、授权 token 相同、语义模型版本相同、文件对象修订号前后一致。
- 删除、修改和完整性校验均位于候选索引副本中；**旧索引永不原地修改**。
- 无变化的更新不生成新代次；空文件/内容清空的文件不导致无限重建。
- 模糊或带账号信息的网页链接不会进入可点击结果；静态数据没有任意命令执行能力。
- Rust Linux 环境完成 207 项单元/集成测试、Clippy `-D warnings`、Rustfmt、编译和 GUI 虚拟显示冒烟。请见根目录 `QA_ALPHA5_INCREMENTAL_20261123.md`。

## 尚未完成（不可当作实现）

- **跨进程持久变更任务队列与断点续建**：当前仍为每次扫描授权范围后在内存副本执行差异更新；变更文件很少时可避免重复 SQL/抽取，但**仍需全量扫描文件目录、整份读取旧快照并完整序列化新快照**。不能称为低 I/O 的真正增量 WAL 分批持久化。
- **规模化语义向量检索**：仍使用准确线性扫描，超过资源预算会显式报错；尚未实现 ANN、多级预过滤和大规模 10 万文档 P95 验证。
- **来源权限持久化、插件进程沙箱及签名协议**：当前为用户手动授权载入的一次性静态数据，不允许代码插件；下次启动需要再次授权。
- **Windows 10/11、银河麒麟、统信 UOS 原生安装、覆盖升级、回滚、签名与卸载**：本轮没有对应目标平台和签名材料，不能声称通过。
- **资源限制和可靠性**：需要复测 300 万文件、10 万文档，冷/热启动、长时内存、异常断电、文件系统事件丢失及安装升级压测。

## 验证命令（Linux）

```bash
python3 scripts/check_release_consistency.py --expected-version 0.18.0-alpha.5
cargo check --workspace --locked --offline
cargo fmt --all --check
cargo clippy --workspace --all-targets --offline -- -D warnings
bash scripts/verify_offline_linux.sh
cargo build --workspace --bins --locked --offline
# 在具备 Xvfb 的 Linux 主机：
xvfb-run -a ./target/debug/xs-ui --standalone --smoke-test --data-dir /dev/shm/xunshu-smoke
```

提示：集成测试使用允许的本地文件系统；在容器里项目安全策略会拒绝 OverlayFS，脚本会自动在 `/dev/shm` 的 tmpfs 创建测试数据，不会关闭路径安全机制。源码包不包含第三方 vendor、编译缓存、大模型及完整安装包。
