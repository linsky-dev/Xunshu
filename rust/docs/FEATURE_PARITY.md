# 0.17 → Rust M1 功能迁移矩阵

版本：**0.18.0-alpha.1（Rust M1）**，2026-11-08。这是完整重写工作的首轮可运行 alpha，**尚未达到旧版全部功能等价**，不使用“100% 完成”或总百分比掩盖未实现的能力。

本矩阵对照旧 [功能映射](../../docs/FEATURE_MATRIX_017.md)、[后续计划](../../docs/ROADMAP.md)、[范围说明](../../docs/SCAN_SETUP.md) 与当前 Rust 源码。旧文档中的已完成标记、旧 Python 测试数量及旧 MFT 性能记录只属于旧基线，不直接成为 Rust 的证据。最终验证与产物见 [VALIDATION.md](../VALIDATION.md)，平台条件见 [PLATFORM_BUILD.md](PLATFORM_BUILD.md)。

状态含义：

- **已重写**：对应入口已有 Rust 实现；验证平台仍以证据注明的范围为限。
- **部分 / 行为改变**：有可用能力，但接口、语义或覆盖范围与旧版不同。
- **基础模型**：只有可测试的纯逻辑组件，尚未接入操作系统采集或产品流程。
- **未迁移**：本 alpha 不可用，也没有回落到 Python 旧引擎的隐藏路线。

## 已改变的使用方式

Rust `xunshu` 是新 CLI，提供 init、status、volumes、scan、search、import-efu、export-efu、import-legacy、migrate-settings、serve 和合成 benchmark 等入口，不承诺旧参数或 `linsearch` Python 模块接口完全兼容。自动化调用者应按 `xunshu --help` 与子命令帮助调整。

名字范围先保存再扫描。范围变更后，旧范围快照停止用于新查询，直到完整扫描发布新代次。取消、权限错误或范围中途变化保留原存储内容；“文件仍保留”不表示收窄授权后仍可继续显示旧范围结果。

旧 schema4/EFU 导入的是可搜索的离线元数据。即使其中写着本地磁盘或网络路径，也不会因此访问这些路径。只有独立保存真实本地范围并完整扫描后，才产生可打开的 local 记录。新设置/索引独立存放，旧版保留作回退对照。

## 后续收敛顺序与验收条件

1. **固化 M1 运行边界**：Win10、Win11、UOS V20 1070 AMD64 分别完成合成回归、原生窗口与交互验收，记录版本、摘要、依赖、权限和路径行为；完成前保持 alpha 标记。
2. **恢复日常入口**：全局双 Ctrl、托盘、自启、所在目录等快捷操作、历史与书签；验证跨应用输入、退出回收及用户主动关闭行为。
3. **接入 MFT/USN**：将 journal 模型接到采集、卷身份、硬链接目录边；先证明完整性与恢复，再建立性能/新鲜度承诺。SCM 依赖此阶段，不能以 stdio 代替服务验收。
4. **恢复授权正文 worker**：独立内容范围、解析预算、身份/策略代次、可终止子进程和缓存撤权；之后接 OCR、语义、阅读定位与 RRF 排序。
5. **完成发行形态**：逐平台安装、升级、回退和卸载，锁定依赖许可、签名与可追溯载荷；不能沿用旧版安装/性能记录作为新 alpha 的通过证明。

上述内容是待实施或待验收工作，不是本 alpha 已交付的功能承诺。每轮根据真实缺陷、合成回归与目标平台证据更新本矩阵。
