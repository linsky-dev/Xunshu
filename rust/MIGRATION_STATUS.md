# Rust 重写进度与下一步验收

> 下文保留 M1 的历史状态。当前恢复版的功能和待验项目以 [验证记录](VALIDATION.md) 为准。

版本：0.18.0-alpha.1 / Rust M1。用户已明确选择全 Rust 重写，因此后期计划中的“保留 PyQt 主界面、逐步双引擎替换”改为独立 Rust 工作区。原始计划的功能与性能目标继续保留；本文件不把架构变更当作验收完成。

## 本轮完成的可运行闭环

- 标准模式：明确范围与类型 → 扫描 → 不可变快照发布 → mmap 加载 → 统一查询 → 原生桌面展示。
- 设置向导：可跳过、可重开、提醒有上限；空结果提供设置入口；扫描进度只显示实际计数。
- 查询：名字、路径、扩展名、大小、日期、来源、布尔组合、正则、通配符、显式拼音及子序列模糊评分；黄金语义与倒排召回对照。
- 数据保护：范围撤销、扫描取消、不完整扫描、陈旧发布、坏快照、只读迁移、EFU 元数据保真、空来源替换与禁用目录保持。
- 增量基础模型：稳定 FileId、父子关系、跨批重命名、目录重命名、删除子树、journal/cursor 不连续时要求重建；尚未接入操作系统事件。
- 工程交付：Rust CLI/UI 构建、合成 300 万条基准、平台构建脚本、依赖锁定、来源与许可清单、验证记录。

## 下一轮执行顺序

### 1. Windows 的真实索引通道

实现按选定本地 NTFS 卷工作的 VolumeProvider、MFT 枚举和 USN reader。将 journal ID、cursor 与新快照作为一次提交；journal 更换、缺口、卷断开或权限变化必须显式重建，不得继续使用错位 cursor。现有 FileId 图模型只保存单一名字，必须扩展硬链接的多父边，避免丢名或重复记录。

验收使用合成 NTFS 测试目录，覆盖创建、连续重命名、跨目录移动、父目录重命名、硬链接、删除子树、重启与 journal wrap。实机只扫描测试目录；不能用全盘扫描替代可控回归。

### 2. 内存与首屏延迟

当前固定记录和名字带虽已去掉每行堆对象，300 万条 mmap 的 RSS 仍超过计划的 120 MB 目标。宽泛查询为获得完整计数与全局评分仍需要检查大量候选。下一步先验证压缩名字块、可选元数据列与更紧凑 posting，再考虑分阶段首屏响应；任何近似或尚未结束的结果必须保留“不完整”标记。

基准须保留语义全量 oracle，避免以漏召回换速度。分别测核心调用、输入到首屏、实际冷启动、后台隐藏后的私有内存。当前 UI 的 80 ms 输入防抖也意味着核心查询毫秒数不能代表计划的 16 ms 端到端指标。

### 3. 桌面可用性与服务边界

完成 Windows 双 Ctrl、托盘、单实例、开机启动的显式选择；实现 UI 与核心独立进程、请求取消、断线重连和版本协商。先验证不同缩放和中文字体，再做文件对话框集成，保持目录与动作授权边界一致。

### 4. 旧功能迁移与内容层

逐项补齐旧版查询长尾、NULL 大小/时间语义、GUI 导入管理、结果动作和内容索引。文件名层、正文、OCR、语义保持独立范围和开关；未经用户选择不启动模型下载、正文读取或远程连接。

### 5. 平台与发布验收

Windows 10/11 x64、UOS V20 1070 AMD64 分别运行完整测试、桌面流程和安装/卸载/升级回退。先通过这些门槛，再制作有签名的正式安装包。当前可运行包是开发验证用 alpha，不应标记为全量替代 0.17.0 的正式发布。

## 持续维护规则

发现问题先留下最小可复现样本，修复后执行对应回归；全量测试与平台构建在交付前集中执行。验证失败要区分代码失败、工具链缺失和运行环境边界拒绝。新能力只有在实际接入并验证后才把 capabilities 标记为 true；模拟模型和编译成功不能替代实机结果。
