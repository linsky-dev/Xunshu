# Xunshu 0.18.0-alpha.3 修复阶段记录（未发布候选）

日期：2026-11-23
来源：`Xunshu-2.0-ReleaseReady.zip`。这是原归档 `0.18.0-alpha.2` 的源代码改造，不是 Windows 安装包，也不是已经验证的 2.0 商业正式版。

## 已在源码中实施（**尚未 Rust 编译及实机验收**）

1. **混合正文检索**：词法/语义各自完整文档候选，经文档 ID 的 RRF 融合，再分页。单文件跨段命中只展示一次，展示证据优先使用词法段落以便高亮。添加 450 文档深页、跨段落去重单元测试。词法单模式继续维持页内候选内存上界。
2. **正文增量复用**：新构建按已授权路径与 `FileRevision` 匹配旧索引；仅在内容授权 token 与语义模型指纹均相等时复用片段和向量。复用旧快照限定 64 MiB，以避免双库无界驻留；超大索引保守退回全量重建。新增复用计数字段和 2 份文档增量测试。
3. **失败不覆盖旧索引**：任何支持格式的文件抽取失败均不会发布新的“部分成功”快照；保留前一版索引，并返回失败报告。对损坏 DOCX 添加回归测试。注意首次构建存在损坏文件时需要修复文件后再建索引。
4. **Frecency 全局排序**：在 `xs-core` Top-K 选择前应用最近使用分数；改掉 UI 分页后二次重排。加权表最多取现有受限 512 条记录。增加尾部命中置顶单元测试。预览结果仍为基础排序，最终结果按加权展示。
5. **安装器事务式回收**：原有 manifest SHA 校验、隔离版本目录和旧数据保留不变；增加 release/probe 归属标记、`cleanup` 子命令、活跃/回退双版本保留、历史安装目录和自检数据安全回收、失败安装的补偿清理。历史自检目录缺归属标记时拒绝自动删除并提示。安装次数不再受无清理 64 条硬限制。更新 `verify-install.py` 对清理/数据保留的合成断言。
6. **连接器安全**：书签读取限制 16 MiB、目录深度 32、条数 20000；Git 远程 URL 在 UI 只显示“已配置（地址隐藏）”，不再输出可能包含令牌的完整地址。新增畸形输入/凭据隐藏测试。
7. **PDF 混合页**：OCR 启用时同时保留 PDF 原生文本和页内嵌图片 OCR，解决仅文本空白页面 OCR 的遗漏（不代表 PDF 所有图片编码均已覆盖）。
8. **Linux 启动器**：原来的空白分词替换为带引号、转义与字段码校验的安全参数解析；明确不经过 Shell，未支持的字段码拒绝执行；新增回归测试。
9. **版本管理**：工作区和 `Cargo.lock` 中的 8 个本地 crate 一起更新到 `0.18.0-alpha.3`；后续发行清单需使用同一版本号。

## 在 Windows 主机执行

1. 建立独立的空验证目录，确保绝不对真实用户的文件目录进行全盘压力扫描。
2. 安装 `rustup` 与锁定工具链，配置 Cargo 依赖缓存（如需要离线构建）；验证 `cargo --version`。
3. 在本目录执行：

```powershell
cargo fmt --all -- --check
cargo test --locked --workspace --offline
cargo clippy --locked --workspace --all-targets --offline -- -D warnings
.\scripts\verify.ps1
.\scripts\build-windows.ps1
```

4. 准备安装载荷资源（OCR、语义模型、字体及许可证；**不得使用缺失资源的伪载荷**），使用 `make-install-payload.py` 生成 `release.json`；另用 `verify-install.py` 对真实模型执行安装/升级/回滚/自检/卸载测试。
5. 正式安装包及签名前须另行完成代码签名、标准 Windows 安装器封装、系统权限适配及交付验收。未通过上述全部检查，不得将本次源码称为 `ReleaseReady`。

> 原仓库要求纯 Rust、默认离线、默认不触碰真实用户磁盘、不升级改写旧 Schema4 数据；本次保持这些边界。
