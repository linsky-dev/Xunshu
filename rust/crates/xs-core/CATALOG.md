# 文件名索引与恢复

新版默认数据目录为 Windows 的 `%LOCALAPPDATA%\XunshuRustV2` 和 Linux 的 `$XDG_DATA_HOME/xunshu-rust-v2`（未设置时用 `~/.local/share`）。索引读取兼容 M1 快照和 `CURRENT.json`。新版快照使用独立的 v2 格式，回退到 M1 时继续使用原数据目录。

- 单段 `.xsi` 通过 mmap 读取，带长度、校验和及结构检查。新格式压缩记录数值列、重复文件名前缀及倒排间隔，原生文件身份和属性独立存放。目录条目和硬链接别名各有独立路径，共享同一文件对象的硬链接可具有相同身份。
- 复合目录 `.xsc` 记录按代次排列的基段、追加段和删除 ID。最多保留八个段，或二十五万个删除 ID，达到上限后合并。读取顺序和同分排序保持稳定。数字 ID 仅属于同一代次。长期选择键由路径和来源组成。
- 写入先生成不可变载荷，再记录可恢复的历史，最后替换 `CURRENT.json`。卷日志标识和游标与载荷一起提交。`CURRENT` 提交后同步异常通过持久化警告表达。确认同步后保留当前及前三个历史代次，旧映射仍在使用时延后回收。
- 仅空库首扫会逐批发布。查询将覆盖标为不完整，取消后保留已经提交的批次。对现有库重扫时，错误或取消保留原索引。范围发生变化后，读侧立即按当前设置拒绝旧范围结果。
- `Store::recover` 只从曾提交且满足当前范围的完整代次恢复，发布为新的索引代次。`PREVIOUS.json` 在 `CURRENT.json` 损坏时提供恢复入口。两个指针均不可验证时需要重新扫描。
- 普通监听用有界路径提示触发增量。Windows 极速模式可从快照游标读入变更，并在成功应用文件增量时更新游标。目录、硬链接拓扑或不连续的卷日志要求完整校准。范围外写入不产生空代次。
- `Index::search_preview` 以相同匹配语义返回预算内可用结果。宽查询可先跳过倒排集合并。调用方应根据完整性字段显示命中下界，并使用同一代次的完整搜索更新计数和分页。
