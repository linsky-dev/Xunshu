# 寻枢 Xunshu 0.18.0-alpha.6 深度工程验收与专业软件差距报告

**日期：2026-11-24 | 基线：0.18.0-alpha.5 | 目标：免费开源、跨平台、本地优先的专业搜索软件**

## 1. 总结与放行结论

本轮完成实际源码改造、Linux 原生构建、211 项独立工作区测试（0 失败、0 忽略）、严格 Clippy、Rustfmt、Xvfb 窗口冒烟、合成文件名及正文性能验证，刷新全部锁定注册表依赖的许可清单，并准备包含用户上传的 Rust 工具链及 Cargo Vendor 的离线工程交付包。版本为 `0.18.0-alpha.6`。**属于可继续开发和 Linux 原型验收的工程预发布版；不属于正式跨平台安装版，不宣称全部完成。** 本轮未复制新增第三方项目的源码，也未增加任何 Cargo 第三方依赖。

在满足现有范围授权、文件身份检查、原子发布等约束的情况下推进可靠性。实际结果优先于历史证据或计划文字。报告中的分数是带明示权重的主观成熟度量尺，不是覆盖率或开发完成百分比。

## 2. 源码实际改造

| 模块 | 本轮改变 | 实际验证及边界 |
| --- | --- | --- |
| `crates/xs-content/src/lib.rs` | `content.pending.idx` 私有候选检查点；成功文档事务提交；每 4096 个变化文档或累计至少 256 个变化且经过 30 秒时尝试落盘；普通抽取失败后保存成功工作 | 新增进程退出/重启复用、故障后原库保护、损坏与重新授权拒绝复用用例通过。只接受同一授权设置修订、模型指纹和正式库修订；不提供未发布查询。不是磁盘 WAL 增量更新，也不是持久事件队列。突然断电最多丢失最后成功检查点后的工作；未执行真实断电/磁盘故障测试。 |
| 同上 | 创建 `segments_doc` 外键辅助索引；每份文档的段落、FTS、向量一并提交；发布前核对基线文件身份 | 避免旧实现按文档统计段落时反复全表扫描；旧库将在下一次真正变更发布时持久保存新索引。索引本体仍受 512 MiB 容量约束。 |
| `crates/xs-content/src/search.rs` | 单查询排名前缀缓存（至多 16,384 文档 ID/分数）；缓存不足的深页回到真实完整排序；索引替换、release 清空缓存 | 新增缓存边界用例。每页仍校验授权与文件修订号；不缓存原始文档文本；只加速相同 FTS 查询，未实现 ANN。 |
| `crates/xs-ui/src/content.rs`、`main.rs` | 展示恢复状态，清除未发布检查点；范围修改后尝试安全清理 | UI 编译/Xvfb 通过，实际人工操作、无障碍、多屏缩放未验收。 |
| `crates/xs-cli/src/main.rs` | `content-discard-checkpoint`；正文授权变动时尝试清理候选库并报告失败 | 只删应用自有候选文件，持有独占正文锁，不删业务文件或正式索引。外部直接修改配置时，候选文件仍可能留在磁盘，下次重建拒绝过期绑定；可手动清理。 |
| `crates/xs-content/tests/content.rs` | 新增失败恢复、损坏/撤权、独立进程退出与再次恢复/清理 | 3 项新增独立集成测试；另有缓存边界 1 项独立单元测试。 |
| `scripts/verify_offline_linux.sh` | 构建并复制抽取工作进程到允许的 tmpfs，再跑完整测试 | 不关闭 OverlayFS、网络文件系统及符号链接安全限制。 |
| `licenses/` | 锁文件 528 个注册表依赖全量清单，875 个检测到的许可/声明文件 | 61 个包未找到单独的通知文件，需要按准确上游版本人工补齐；不可宣称许可证审计全部通过。 |

对抗式剩余风险：检查点是正文的额外本地副本，不能代替加密存储或可证明的数据擦除；跨进程只能从已成功写入的候选快照恢复；目录仍需重扫、候选仍需整体序列化，写放大尚未消除；512 MiB 快照上限与精确语义扫描预算在多文档、长文档上会遇到扩展性瓶颈；恶意篡改整个本地应用数据目录属于更强的攻击模型，SHA-256 不提供来自可信签名者的真实性。

## 7. 离线工程包与需要的环境

已包含：用户提供的 Linux x64 Rust 1.99.1 官方发行 tar、Cargo Vendor tar.gz（原始包完整保留）、最新源码、5 个 Linux Debug 程序、环境清单、QA 日志、SHA256SUMS、离线 bootstrap 脚本。原生二进制强 GLIBC 符号需求 CLI/工作进程/安装器 2.34、UI 2.35；这只是 ABI 必要条件，不能当作 UOS/麒麟认证。目标系统仍须提供 X11/Wayland、Mesa/OpenGL、字体、D-Bus 等，系统包清单随附，不内置整套 Linux。

正式安装仍缺：
1. `resources/`：`bge.onnx`、`bge-tokenizer.json`、`ppocr-det.onnx`、`ppocr-rec.onnx`、`ppocr-dictionary.txt`、`libonnxruntime.so`（Linux）/`onnxruntime.dll`（Windows）、`inference.json` 及上游许可证/模型卡。已有 `scripts/prepare-models.py` 按固定来源准备，不能用空模型文件伪造通过；官方 BGE/Paddle/ORT 下载地址、摘要在该脚本中。转换依赖见 `docs/RECOVERY.md`；字体 Noto Sans SC 与许可用于安装载荷。
2. Windows 原生 x86_64 MSVC Rust 1.99.1、Visual Studio Build Tools 的 C++ 桌面开发组件与 Windows SDK；必须在 Windows 实机上生成/验收对应产物，不能用 Linux ELF 代替 EXE。
3. UOS/麒麟目标版本/架构的本机或虚拟机、相应工具链、系统库，实机验证；签名证书（如果选择签名发行）。

离线重建：解包后在 Linux x86_64 运行 `bash bootstrap-linux.sh /path/to/new-workspace check`，也可选择 `test` / `build` / `release`。用户无需重复下载已提供的 Rust/Vendor。当前交付包**不是带全部模型和所有平台运行环境的最终安装包**。
